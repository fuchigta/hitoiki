# はじめに

インストール後の最初の起動と、最初にやることをまとめます。インストール方法は [インストール](./install.md) を参照してください。

## 初回起動

常駐アプリ `hitoiki-app.exe`（スタートメニューの「Hitoiki」）を起動すると、タスクトレイに常駐して記録を始めます。初回だけ、使い方の案内（オンボーディング）がウインドウで開きます。

- ウインドウを閉じても常駐は続きます。止めるときは、トレイのアイコンのメニューから「終了」を選びます（そのときの区間は閉じて保存されます）。
- 記録は起動した時点から始まっています。案内の途中でも、何もしなくて構いません。
- 前面のウインドウ（アプリ名とタイトル）と無操作の時間、Claude Code / Codex のログを記録します。キー入力は記録しません。詳しくは [プライバシー](./privacy.md) を参照してください。
- Hitoiki 自身のウインドウを操作している時間は記録しません（記録の空白になります）。記録したい場合は [設定](./configuration.md) の `collect.record_self` を有効にします。

## オンボーディング

案内は次の 5 ステップです。「次へ」「戻る」で移動でき、途中のステップはスキップできます。

1. **ようこそ**: 何を記録するか、データがこの PC にだけ保存されることの説明です。
2. **いまやることを 1 つ決める**: タスク名を入れて「作って開始」を押すと、タスクを作って進行中（doing）にします。進行中のタスクがあると、ルールに当たらない時間はそのタスクの候補になります。
3. **自動起動と通知**: ログオン時の自動起動（`general.autostart`）の切り替えと、新しいバージョンの確認（`general.update_check`。「新しいバージョンを確認する（1日1回、GitHub に問い合わせます。送る情報はありません）」を はい／いいえ で選びます。選ばずに進むと確認しません）、「テスト通知を出す」ボタンがあります。
4. **カレンダー（任意）**: ICS の URL を登録すると、会議の時間を自動で判定できます。登録方法は [設定](./configuration.md#カレンダー) を参照してください。
5. **日々の使い方**: 各画面への案内です。「はじめる」で完了します。

完了の状態は保存され、次回からは自動では開きません。もう一度見たいときは、設定画面の「オンボーディングをもう一度見る」か、コマンドラインから `hitoiki ui onboarding` を実行します。

## 最初にやること

1. 進行中のタスクを 1 つ作ります（オンボーディングの手順 2、または [タスク](./daily-use.md#タスク) 画面、`hitoiki task add "タイトル"` と `hitoiki task start <id>`）。
2. 「テスト通知を出す」で通知が出ることを確認します。出ないときは [トラブルシューティング](./troubleshooting.md) を見てください。
3. しばらく普通に作業します。「今日」画面にタイムラインが並びます。
4. 帰属が決まらなかった時間は「要確認」として溜まります。余裕のあるときに「仕分け」画面で確定します（[日々の使い方](./daily-use.md#仕分け)）。同じ作業を何度も仕分ける場合は、帰属ルールを作ると自動で振り分けられます。
5. うまく動かないときは `hitoiki doctor` で診断します。

コマンドラインの使い方は [CLI リファレンス](./cli.md) にあります。
