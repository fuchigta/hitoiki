# プライバシー

Hitoiki は、個人の自己管理のために自分の PC の中だけで動くことを前提に作っています。会社の PC に導入するかの判断材料として、記録するもの・しないもの、通信が起きる場面をまとめます。

## 原則

- **ローカル完結**: データはすべてこの PC の SQLite に保存します。同期・クラウド保存・テレメトリ（利用状況の送信）はありません。
- **ネットワークポートを開かない**: 待ち受け用の HTTP サーバやローカルポートは持ちません。常駐アプリと CLI のやり取りは Windows の名前付きパイプ（`\\.\pipe\hitoiki-<ユーザー SID>`）で行い、作成したユーザーだけがアクセスできます。画面は Tauri の WebView の中でだけ表示し、ブラウザ向けには配信しません。
- **キー入力を記録しない**: キーの内容も回数も取得しません。低レベルのキーボード/マウスフック（`WH_KEYBOARD_LL` など）、DLL インジェクション、他プロセスのメモリ読み取りは使いません。
- **管理者権限を要求しない**: 公開された低権限の Windows API だけを使います。
- **評価をしない**: 時間の使い方の良し悪しを判定せず、通知や AI 振り返りの文言にも評価を含めません。

## 記録するもの

| 対象 | 内容 |
|---|---|
| 前面ウインドウ | 前面になったウインドウのアプリ名（exe 名とパス）、ウインドウタイトル、その開始・終了時刻 |
| 無操作 | 最後の入力から一定時間（`collect.idle_threshold_sec`）経ったこと、ロック・スリープの時間。**入力があったかどうかの時刻だけで、入力の中身は見ません** |
| エージェントのログ | Claude Code / Codex のセッションログ（`~/.claude`、`~/.codex` 配下）から、セッションの開始・終了、プロンプトの送信、応答の完了の時刻、作業ディレクトリ、ブランチ。プロンプトは**先頭の抜粋**（既定 200 文字。`agent.prompt_excerpt_chars` で変更、0 で保存しない）のみ |
| カレンダー | 設定した ICS から取り込んだ予定（タイトル、時間、場所） |
| あなたの入力 | タスク、計画、チェックイン、ハッスル、ABC の記録、OKR、スキル、振り返りの回答 |
| 通知のログ | 出した通知の種類、時刻、あなたの応答 |

## 記録しないもの

- キー入力の内容と回数、マウスの動き。
- 画面の内容（スクリーンショット）、ウインドウ内のテキスト、クリップボード。
- ブラウザの閲覧履歴や、ページの中身。拡張機能から詳細を受け取る補助コレクタの口（`hitoiki ingest context`、`native-host`）はありますが、拡張機能自体はこのリポジトリにはなく、受け取った内容は保存するだけで判定には使っていません。
- 除外ルールに一致したウインドウのパスとタイトル。既定でパスワードマネージャ（KeePass 系、1Password、Bitwarden）とプライベートブラウズのウインドウが対象です（[設定](./configuration.md#除外ルール)）。
- Hitoiki 自身のウインドウを操作している時間（`collect.record_self` を有効にしない限り）。
- 非対話のエージェント実行（`claude -p` や `codex exec` など）の時間。

## 保存場所

| 用途 | パス |
|---|---|
| 設定 | `%APPDATA%\hitoiki\config.toml` |
| DB | `%LOCALAPPDATA%\hitoiki\hitoiki.db` |
| ログ | `%LOCALAPPDATA%\hitoiki\logs\`（日次ファイルを 14 日分。古いものは自動で削除） |

アンインストールしてもこれらは残ります。消したい場合は手動で削除してください（[インストール](./install.md#アンインストール)）。DB は暗号化していないので、PC のユーザーアカウントとディスクの保護が前提です。

## ネットワーク通信が発生する場面

Hitoiki がネットワークに出るのは、次の場面だけです。いずれも利用者が明示した場合に限ります。

| 場面 | 条件 | 送る内容 |
|---|---|---|
| ICS カレンダーの取得 | `calendar.sources` を設定したとき（定期） | 設定した URL への取得リクエスト |
| OpenAI 互換の判定器 | `judge.enabled = true` かつ `type = "openai-compatible"` のバックエンドを使うとき | 区間のアプリ名・ウインドウタイトル・作業ディレクトリ、進行中のタスクなど |
| 最新版の確認（手動） | `hitoiki version --check` を実行したとき | GitHub Releases への問い合わせ |
| 最新版の確認（定期） | `general.update_check = true` にしたとき（オンボーディングか設定画面で選ぶ。未設定なら行わない）。起動の数分後と、その後 1 日 1 回 | GitHub Releases への GET リクエストだけ。User-Agent は `hitoiki/<バージョン>` で、識別子・利用状況・記録の内容は送らない |
| `hitoiki doctor --network` | 指定したとき | カレンダー取得・判定器への疎通確認 |

次の 2 つは Hitoiki 自身は通信しませんが、**外部コマンドが通信する可能性**があります。利用するコマンドの挙動を確認してください。

- **AI コマンド**（`ai.command`、既定 `claude -p`）: 振り返りの問いを作るとき、集計、タスク名、計画、カレンダーの予定名、チェックイン、ハッスル、ABC 記録、OKR などの文脈をプロンプトとして渡します。ウインドウタイトルは含みません。既定の `claude -p` はクラウドの AI に送られます。
- **外部コマンド型の判定器**（`type = "external-command"`）: 区間のアプリ名・タイトル・作業ディレクトリなどを標準入力で渡します。

この PC の外にデータを出したくない場合は、`judge.enabled` を false（既定）のままにし、カレンダーを登録せず、AI 振り返りを使わなければ、通信は発生しません。

## ログに出さないもの

ログと診断メッセージ（`hitoiki doctor` の出力を含む）には、次のものを出しません。

- ウインドウタイトル
- プロンプトの内容
- カレンダーの ICS URL（カレンダーはソース名だけを出します）

ログに出すのは、起動・終了・収集の開始と停止・スレッドの異常終了（panic はファイル名と行番号だけ）・再計算やカレンダー同期の件数やエラー・起動引数（`--screen` など）といった動作の記録です。`hitoiki doctor` の「対応付けできなかったプロンプト」の診断には、前面だったアプリの exe 名（`chrome.exe` など）だけを使います。記録が止まっていた時間を求めるための収集の稼働（開始と最終確認の時刻）は DB の `setting` に保存します。

判定器の API キーは設定ファイルに書かず、環境変数名（`api_key_env`）で指定します。
