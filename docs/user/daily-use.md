# 日々の使い方

常駐アプリ（`hitoiki-app.exe`）の画面と通知、トレイの使い方です。同じことはすべてコマンドラインからもできます（[CLI リファレンス](./cli.md)）。

画面は左のメニューから切り替えます。コマンドラインからは `hitoiki ui <画面>` で開けます（画面名は [CLI リファレンス](./cli.md#hitoiki-ui-の画面名)）。

## 今日

一日の流れを確認する画面です（`today`）。

- **いま**: 進行中（いまの枠があればその枠も）と、進行中（doing）のタスクの開始からの経過時間。「完了にする」で終えられます。
- **今日の合計**: 記録された時間の合計と、そのうちエージェント対話の時間。無操作と休憩は合計に含めません。
- **確認待ち**: 「要確認 N 件」と、今日の分のおよその長さ。「仕分けを開く」で仕分けへ移れます。
- **タイムライン**: 予定（カレンダー）・計画ブロック・実績を縦に並べ、現在時刻の線を引きます。Hitoiki が動いていなかった時間帯（PC の電源が切れていた、アプリが終了していた、収集が止まっていたなど）は、実績の行に斜線の「記録なし」で重ねて表示します。無操作やロックの時間とは別です。種別ごと・タスクごとの内訳も出ます。
- **未回答の問いかけ**: 答えなかった通知。答えなくても構いません。
- カレンダーを登録していないときは、「カレンダーをつなぐと会議を自動判定できます」と 1 回だけ案内します（閉じると二度と出ません）。

### 1 日をデザインする

今日の画面のタイムラインの「計画」の列で、ブロック（時間の枠）を直接作れます。

- **作る**: 空いている所を上下にドラッグ（15 分刻み）、またはクリック（1 時間）して、ラベル・タスク・集中を入れて「追加」。
- **タスクをその場で入力する**: フォームの「タスク」は検索できる選択欄です。文字を入れると未完了のタスクがタイトルの部分一致（大文字小文字は区別しない）で絞り込まれます。↑↓ で選び、Enter で決定、Esc で候補を閉じます。一致するタスクがなければ「新規作成: 『入力した文字』」が出て、選ぶとその場でタスクを作ってブロックに割り当てます。
- **動かす・伸ばす**: ブロックをドラッグで動かし、上端・下端をドラッグして長さを変えます。クリックで編集、「×」で削除。ほかのブロックや予定と重なる場合は、フォームに知らせます（重ねても保存できます）。
- **今日のデザイン**: 1 日の初め（今日のブロックが 0 件のとき、始業の通知をクリックしたとき、振り返りの案内から、タイムラインの「今日のデザイン」ボタン）に開くモードです。テンプレートの適用、今日のカレンダー予定、ブロックにしていない未完了タスクの一覧が並びます。タスクはタイムラインへドラッグするか、選んでからタイムラインをクリックするとブロックになります。終わったら「完了」を押すと通常の表示に戻ります。

### ブロックのテンプレート（働き方のパターン）

「水曜は定例があるのでこの並び」「金曜は内省の時間を取る」といった配置を、名前を付けて保存できます。

- **保存**: 配置してから「この日の配置をテンプレートとして保存」。計画画面の「テンプレート」でも、ブロックと時刻（HH:MM）を指定して作ったり編集したりできます。
- **曜日の既定**: テンプレートに曜日（複数可）を割り当てておくと、その曜日の「今日のデザイン」で「水曜日のパターンを適用しますか？」と提案します。
- **適用**: テンプレートを選ぶと、作られるブロックと、既存のブロック・予定（busy）との重なりをプレビューします。重なる枠は「作らない」か「重ねて作る」かを選べます。「直前の適用を取り消す」でその適用で作ったブロックだけを消せます。
- テンプレートがまだ無いときは「よく使うパターンを保存しておくと、毎朝ワンタップで並べられます」と案内します。

## 仕分け

自動判定に確信が持てなかった区間（要確認）を確定する画面です（`review`）。期間（今日・昨日・今週・先週）を選んで一覧し、区間ごとに次を指定して「確定」します。

- **タスク**: 割り当てるタスク。
- **種別**: 作業・エージェント対話・会議・割り込みなど。
- **活動**: 「コードレビュー」のような活動ラベル。
- **この条件を常にこのタスクに**: チェックすると、その区間から帰属ルールを作り、以後は同じ条件が自動でそのタスクになります。
- **割り込みとしてタスク化**: 区間のタイトルから新しい割り込みタスクを作って割り当てます。

1 分（`review.min_sec`）未満の短い区間は、一覧に出さずに隠します。「短い区間 N 件を表示」のチェックで表示できます。隠した区間も削除はされず、そのまま集計に含まれます。今日の画面の「確認待ち」の件数は、隠している短い区間を含めず、短い区間の件数を別に添えます。なお、タスクバーやスタートメニューなどを一瞬だけ前面にした時間は、そもそも独立した区間にせず前後の作業に含めます（[設定](./configuration.md)の `collect.transient_exes`）。

確定した内容は最優先で適用され、再計算しても上書きされません。

### 無操作の時間をワンタップで仕分ける

種別が「無操作」の区間には、「休憩」「会議」「考えごと」「離席」のボタンが並びます。押すとその場で確定します。

| ボタン | 保存される内容 |
|---|---|
| 休憩 | 種別: 休憩 |
| 会議 | 種別: 会議 |
| 考えごと | 種別: 作業、活動: 考えごと（タスクは付けない） |
| 離席 | 種別: 休憩、活動: 離席 |

CLI では `hitoiki review idle <区間 ID>... <break|meeting|thinking|away>` です。

次の場合は、そもそも仕分けの対象になりません。
- 画面ロックやスリープによる無操作が `review.auto_break_locked_min`（既定 10 分）以上続いたときは、自動で「休憩」になります（`0` で無効）。違う場合は、あとから上のボタンで付け替えられます。
- 予定（busy）と重なる無操作は、これまでどおり「会議」になります。

### 戻ってきたときの確認

予定外の無操作が `push.idle_return_min`（既定 15 分）以上続いたあと復帰すると、「さっきの N 分は、どう過ごしていましたか？」と通知します。ボタン（休憩・会議・考えごと・離席）を 1 回押すだけで、上と同じ内容で確定します。答えなくても構いません。`push.idle_return_min = 0` か、`push.disabled_triggers` に `idle_return` を入れると出ません。

### まとめて仕分ける

区間の左のチェックで複数を選ぶと、上のバーから同じタスク・種別・活動を一括で割り当てられます（「この条件を常にこのタスクに」も使えます）。CLI では `hitoiki review set <区間 ID>... --task T` のように複数の ID を渡します。

### ルール化の提案

同じ exe（エージェントの区間なら作業ディレクトリ）の区間を、同じタスクにあわせて 3 回（`review.rule_suggest_min_count`）以上確定すると、一覧の上に「Orca.exe はいつもこのタスクにしますか？」と出ます。「ルールにする」で帰属ルールを追加し、「今はしない」で断ります。断った組み合わせは 14 日（`review.rule_suggest_snooze_days`）出しません。ルールの追加は、すでにあるルールと同じ内容なら再利用します。CLI では `hitoiki review suggest` で一覧し、`--accept N` / `--dismiss N` で操作します。

### 無視する（ノイズのアプリ・区間）

タスクバーやスタートメニューなどのシステム系アプリ（`explorer.exe` など）は、短く前面になるだけで区間を増やします。これらは既定の「無視リスト」（`collect.ignore_exes`）に入っていて、短いものは前後の作業に含め、続いたものは「無視」の区間にします。無視の区間は集計・仕分け・レポート・タスクの実績・通知に数えず、今日のタイムラインには薄く表示します（今日の合計の下に「無視 N」と添えます）。記録は消えません。

- **区間を無視する**: 仕分け画面で区間を選び「この区間を無視」、または複数選んで「N件を無視する」。今日のタイムラインでは範囲を選んで開く「実績の付け替え」で、チェックした区間を「チェックした区間を無視」できます（区間全体が対象）。同じ画面の「無視した区間」から「元に戻す」で取り消せます。CLI は `hitoiki review ignore <区間 ID>...` と `hitoiki review unignore <区間 ID>...` です。
- **このアプリを今後も無視**: 仕分けの区間の「○○.exe を今後も無視」で無視リストに追加し、直近 7 日を再計算します。設定画面の「無視するアプリ」や `hitoiki ignore add|remove <exe>` でも変更できます。リストから外せば元に戻ります。
- **無視の提案**: 直近 7 日の記録から、短い区間が多いアプリ（10 秒未満が 7 割以上で 20 件以上）、既知のシステム系アプリ、要確認に短い区間が何度も出ているアプリ、仕分けで「無視」「タスクなし」にした回数が多いアプリを、仕分け画面の上に「explorer.exe は短い区間が 214 件（合計 16.5分）。無視しますか？」と出します。「無視する」で追加して再計算、「今回はしない」で 30 日は出しません。ターミナル・エディタ・ブラウザ・通信・会議のアプリは提案しません。CLI は `hitoiki ignore suggest [--accept EXE] [--dismiss EXE] [--days N]` です。

### 始めたタスクを信頼する

設定 `review.trust_doing = true`（設定画面とオンボーディングにも切り替えがあります）にすると、進行中のタスクに仮で当てた時間も確認待ちにせず、そのタスクの自動判定（根拠: 進行中のタスク）として扱います。既定は従来どおり、確認待ちにします。

## 実績の補正

自動判定とあとからの仕分けでは直しにくい「この時間帯はまるごとあのタスクだった」を、範囲を選んで一度に直せます。実績の入力欄ではなく、ユーザーの確定（`segment_override`）として保存されるので、再計算しても残ります。

1. 今日の画面のタイムラインで、「実績」の列をドラッグして時間帯を選びます。ドラッグの端は、2 分（`review.snap_sec`、`0` で吸着しない）以内なら区間の境目にくっつきます。
2. 下に「実績の付け替え」が開きます。範囲に含まれる区間が一覧で出るので、チェックで対象を選び、割り当て先（タスク、「タスクなし」、「休憩」）と、任意で活動を選びます。
3. 一覧の下に「タスク X に 1時間12分を割り当て（うち PC 外 15分）。外した区間 3 件」のように、確定前の合計が出ます。「付け替える」で確定します。

最初のチェックは次のとおりです。

| 区間 | 最初のチェック | 設定 |
|---|---|---|
| 通常の作業（自動・要確認） | ON | |
| エージェント対話・見守り | ON（タスクだけ付け替え、種別は維持） | |
| ユーザーが確定済みの区間 | OFF（チェックすれば上書きできる） | `review.correct_include_confirmed` |
| 会議（カレンダー由来） | OFF | `review.correct_include_meeting` |
| 無操作・記録なし | OFF | `review.correct_include_idle` |

一覧の上の「未確定だけ」「タスクなしだけ」で絞り込め、「無操作・記録なしも含める」で無操作と記録なしをまとめて切り替えられます。範囲の境界にまたがる区間は、範囲の内側の部分だけが対象です（区間の残りは変わりません）。

### PC 外の作業

無操作や記録なし（Hitoiki が動いていなかった時間帯）を含めてチェックすると、その時間は、選んだタスクの「作業」として計上され、「PC 外」の印が付きます（タイムラインでは斜線の入った区間、一覧では「PC 外」のタグ）。会議室や紙での作業など、PC に触れていなかった時間を実績に入れるための機能です。記録なしの時間帯は、補正すると「記録なし」の斜線ではなく、その区間として表示されます。

### 取り消す

付け替えは 1 回ごとにひとまとまりで記録されます。確定の直後は「取り消す」ボタンで、あとからはタスクの詳細の「補正した時間帯」から取り消せます。取り消すと、その補正で作った確定を削除して、その時間帯を自動判定の結果に戻します（再計算するため、対象の時間帯の判定は最新のルールで作り直されます）。

CLI は `hitoiki review set --from <時刻> --to <時刻> --task <ID>`（`--dry-run` で確定せずに対象と合計だけを表示）、`hitoiki review corrections`、`hitoiki review undo-correction <ID>` です（[CLI](./cli.md)）。

## 通知

Hitoiki は、ときどき通知で「いま何してた？」などと問いかけます。ボタンを 1 回押すだけで答えられ、答えはチェックイン・ハッスル・通知の一時停止として保存されます。答えなくても構いません。

主な問いかけの場面は、始業・終業・週次の振り返り、無操作から戻ったとき、割り込みの後、会議が延びているとき、切り替えが多いとき、長時間の集中、遅い時間までの作業です。1 日の上限（既定 6 件）と最小間隔（既定 60 分）があり、会議中や集中ブロックの計画中は保留されます。回数や時刻は [設定](./configuration.md#通知) で変えられ、`push.enabled = false` で止められます。

通知は Windows のトースト（ボタン付き）です。出せない場合は、画面右下の小さなポップアップに切り替わります。通知本体をクリックすると、該当する画面（振り返りなど）が開きます。ボタンが効かない場合は [トラブルシューティング](./troubleshooting.md#通知が出ない場合) を参照してください。

設定画面とトレイの「通知を 1 時間止める」で一時的に止められます。通知のボタンに「今日はもういい」が出る場合は、その日の終わりまで止まります。

## 振り返り

始業・終業・週次の問いを AI に作らせ、回答を書いて保存する画面です（`reflect`）。

- 種別（始業・終業・週次）と基準日を選び、「問いを生成」を押します。
- 問いは種類ごとのフォームで答えます（`ai.structured` が有効なとき。既定では `claude` を使っている場合）。チェックインは 1〜5 のボタンと ERG タグ・メモ、ハッスルはテキストと強さ、ABC は A（AI が記録から推測した候補で、書き換えられます）・B・C の感情と強さ・反論、自由記述は文章です。答えた問いだけが保存され、チェックイン・ハッスル・ABC は「記録」画面にも出ます。ABC は保存後に、受け止め方を掘り下げる問いを AI に続けて聞けます。残りの問いは後から答えられます。
- 構造化に失敗したときは、従来どおり Markdown の問いが出るので、回答を Markdown で書いて保存します。過去の振り返りも一覧から開けます。
- 時間の使い方に良し悪しの評価はつけず、問いかけの形で寄り添います。

AI の呼び出しは、設定 `ai.command`（既定 `claude -p`）で指定したコマンドに標準入力でプロンプトを渡す方式です。Hitoiki 自身はネットワークに接続しません。コマンドが使えない環境では、[設定](./configuration.md#ai-コマンド) を見直してください。

## タスク

タスクの作成・編集・状態変更をする画面です（`tasks`）。

- 状態は「未着手」「進行中」「完了」「やめた」。進行中にできるタスクは、既定では 1 つだけです（`task.single_doing`）。
- 緊急・重要のフラグ、見積もり（任意）、本文（Markdown）、スキル、リンク（Issue など）を付けられます。実績時間の入力欄はありません。実績は記録から自動で算出されます。
- 割り込みタスクは通常のタスクと区別されます。
- **保存**: 編集は「保存」ボタン（本文の下とフォームの最下部）か Ctrl+S で保存します。自動保存はしません。保存すると「保存しました」を数秒表示し、失敗したときはボタンの近くにエラーを出します。
- **未保存の確認**: 保存していない変更があると「未保存の変更があります」と表示し、保存ボタンを強調します。そのまま別のタスクを選ぶ、別の画面へ移ると、破棄してよいかを確認します（「キャンセル」で留まります）。
- **本文のプレビュー**: 本文は「編集」と「プレビュー」を切り替えられます。タスクを開いたときは、本文があればプレビュー、空なら編集です。
- **補正した時間帯**: そのタスクへ付け替えた時間帯（[実績の補正](#実績の補正)）の一覧です。合計と PC 外の時間を確認し、「取り消す」で戻せます。
- **帰属ルール**: 「アプリ名」「ウインドウタイトル」「作業ディレクトリ」「リポジトリ」「URL」「ブランチ」のパターン（glob / 正規表現 / 含む）をタスクに結び付けます。条件に当たる時間は自動でそのタスクになります。
- **やめると削除**: 「やめる」はタスクを「やめた」状態にして、これまでの記録（計上した時間）を残します。誤って作ったタスクは詳細の下の「削除」で消せます。押すと確認が出て、「計上済み 1時間20分（12 区間）と確定した割り当て 3 件が未割り当てに戻ります。帰属ルール 2 件も削除されます」のように影響を表示し、「削除する」で実行します。削除すると、そのタスクの本体・帰属ルール・スキルの紐付け・進行中の履歴・確定した割り当てと補正が消え、計上されていた時間は未割り当てに戻って仕分けの対象になります（再計算するので、直近の判定はそのときのルールで作り直されます）。計画のブロックとテンプレートの項目は消えず、タスクの指定だけが外れます（ラベルが空ならタスク名がラベルになります）。削除は元に戻せません。

### クイック入力（割り込みのとき）

割り込みなどで、考える間もなくタスクを切り替えたいときの小さな入力窓です。どの画面・どのアプリからでも、ショートカット（既定は `Ctrl+Alt+Space`。[設定](./configuration.md#クイック入力のショートカット)）かトレイの「タスクを素早く入力…」で開きます。

1. ショートカットを押すと、画面の中央上寄せに入力窓が開き、すぐ入力できます。
2. タスク名を入れると未完了のタスクが絞り込まれ、↑↓ と Enter で選ぶと、そのタスクを開始（進行中に切り替え）します。一致がなければ「新規作成: 『…』」を選んで Enter で、作成して開始します。
3. 先頭に `!` を付ける、または Tab で「割り込み: オン」にすると、新規作成するタスクを割り込み（緊急）として作ります。
4. 候補の先頭には「戻る: 〇〇」が出ます。割り込みが終わったら Enter で直前まで進行中だったタスクに戻れます（空欄のまま Enter でよい）。
5. 開始すると窓に「開始しました: 〇〇」を一瞬出して閉じます。Esc を押すか、ほかの場所をクリックして入力窓がフォーカスを失った場合も閉じます。

ショートカットは GUI アプリが動いているときだけ使えます（ヘッドレスの daemon にはありません）。他のアプリが同じ組み合わせを使っていると登録できないので、設定画面で別の組み合わせに変えてください。CLI では `hitoiki task switch` / `hitoiki task back` が同じことをします（[CLI](./cli.md)）。

## 計画

タイムブロッキングの画面です（`plan`）。「計画」の列を上下にドラッグして 15 分刻みでブロックを作り、タスクやラベルを結び付けます。「集中」にしたブロックの間は、通知が保留されます。カレンダーの予定と実績を並べて見られます（計画と実績）。

## 記録

その時の気持ちや出来事を残す画面です（`records`）。

- **チェックイン**: エネルギー・気分・ストレスを 1〜5 で。一言メモも書けます。
- **ハッスル**: その日の気になったこと（デイリーハッスル）と強さ。
- **ABC の記録**: 出来事（A）、受け止め方（B）、感情（C）の記録。AI に受け止め方を掘り下げる問いを作らせることもできます。

## OKR・スキル

目標（Objective）とその成果指標（KR）、スキルを管理する画面です（`okr`）。タスクを KR やスキルに結び付けると、レポートで目標別・スキル別の時間が見られます。スキルは階層にでき、同梱のプリセットを取り込めます。複数のスキルが付いた時間は、それぞれに全時間を数えます。

## レポート

期間内の時間を集計する画面です（`report`）。期間（今日・昨日・今週・先週・任意の期間）と、集計の軸（タスク・活動・象限・OKR・スキル・エージェント・種別）を選びます。

## 設定

`settings` 画面では、自動起動、通知の受け取り、クイック入力のショートカット、新しいバージョンの確認（[更新の確認](./configuration.md#更新の確認)）、テスト通知、通知の一時停止、オンボーディングの再表示ができます。「設定ファイル」では、キーと値（TOML）を指定して任意の設定を書き換えられます。設定の内容は [設定](./configuration.md) を参照してください。

## トレイ

常駐中はタスクトレイにアイコンが出ます。メニューには次の項目があります。

- 現在のタスク（「いま: ...」）と今日の合計
- **タスクを切り替え**: 未完了のタスクから選んで開始
- **タスクを素早く入力…**: クイック入力の窓を開く（登録中のショートカットを併記）
- **チェックイン（エネルギー）**: 1〜5 を選ぶだけで記録
- **ハッスルを記録…**
- **新しいバージョン vX.Y.Z をダウンロード…**: 新しい版が見つかっている間だけ出る（`general.update_check` が `true` のとき）。押すとリリースページをブラウザで開く
- **UI を開く**
- **通知を 1 時間止める**（止めている間は「通知の一時停止を解除」）
- **終了**: 常駐を止める。進行中の区間は閉じて保存されます

ウインドウを閉じても常駐は続きます。ログオン時に自動で起動したい場合は `general.autostart` を有効にします（既定で有効）。
