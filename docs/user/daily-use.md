# 日々の使い方

常駐アプリ（`hitoiki-app.exe`）の画面と通知、トレイの使い方です。同じことはすべてコマンドラインからもできます（[CLI リファレンス](./cli.md)）。

画面は左のメニューから切り替えます。コマンドラインからは `hitoiki ui <画面>` で開けます（画面名は [CLI リファレンス](./cli.md#hitoiki-ui-の画面名)）。

タスクの編集など、保存していない変更があるときに別の画面へ移ろうとすると（メニュー、ブラウザの「戻る」「進む」のどれでも）、「破棄して移動しますか？」と確認します。

## 今日

一日の流れを確認し、計画（ブロック）を立てる画面です（`today`）。以前の「計画」の画面は、この画面に入りました（古い呼び名の `plan` も使えます）。

- **日付の帯**: 「‹」「›」で前の日・次の日へ、「今日」で今日へ戻ります。日付の欄から日を選ぶこともできます。ブラウザの「戻る」「進む」でも日付をたどれます。右端の「デザイン」は今日のデザイン（下記）の開閉、「0〜24 時を表示」は表示する時間帯の切り替えです。
- **上の帯**（今日を見ているとき）:
  - **いま**: 進行中（doing）のタスクと、開始からの経過時間。いまの計画ブロックと同じタスクなら 1 行にまとめ、ブロックの時刻と「集中」の印を添えます。「完了にする」で終えられます。
  - **今日の合計**: 記録された時間の合計と、そのうちエージェント対話の時間。無操作と休憩は合計に含めません。
  - **要確認**: 「要確認 N 件」と、今日の分のおよその長さ。「実績で確認する」で実績の要確認へ移れます。
  - **未回答の問いかけ**: 件数。「答える」で右のパネルに一覧が開きます（下の「あとから答える」）。
  今日以外の日を見ているときは、その日の合計だけを出します。
- **タイムライン**: 予定（カレンダー）・計画ブロック・実績を縦に並べ、今日なら現在時刻の線を引きます。Hitoiki が動いていなかった時間帯（PC の電源が切れていた、アプリが終了していた、収集が止まっていたなど）は、実績の行に斜線の「記録なし」で重ねて表示します。無操作やロックの時間とは別です。
- **右のサイドパネル**: 何も開いていないときは畳まれ、タイムラインが全幅になります。次のものが同時に 1 つ開きます。
  - ブロックの作成・編集（計画の列）。
  - 実績の付け替え（実績の列のドラッグ。下の「実績の補正」）。
  - 区間の詳細（実績の列のクリック）。実績の画面と同じ形でタスクなどを確定でき、「実績で開く」リンクもあります。
  - 今日のデザイン、未回答の問いかけ。
- **内訳**: タイムラインの下に、種別ごと・タスクごと（上位）の内訳が並びます。見出しの「レポートで見る」からレポートへ移れます。
- カレンダーを登録していないときは、「カレンダーをつなぐと会議を自動判定できます」と 1 回だけ案内します（閉じると二度と出ません）。

### 1 日をデザインする

タイムラインの「計画」の列で、ブロック（時間の枠）を直接作れます。どの日でも作れます（前日・翌日に移って作ることもできます）。

- **作る**: 空いている所を上下にドラッグ（15 分刻み）、またはクリック（1 時間）すると、右のパネルに入力フォームが開きます。ラベル・タスク・集中を入れて「追加」。
- **タスクをその場で入力する**: フォームの「タスク」は検索できる選択欄です。文字を入れると未完了のタスクがタイトルの部分一致（大文字小文字は区別しない）で絞り込まれます。↑↓ で選び、Enter で決定、Esc で候補を閉じます。一致するタスクがなければ「新規作成: 『入力した文字』」が出て、選ぶとその場でタスクを作ってブロックに割り当てます。
- **動かす・伸ばす・消す**: ブロックをドラッグで動かし、上端・下端をドラッグして長さを変えます。クリックすると右のパネルで編集でき（ブロックは強調表示になります）、削除はパネルの「…」メニューか、ブロックの「×」です。ほかのブロックや予定と重なる場合は、フォームに知らせます（重ねても保存できます）。
- **今日のデザイン**: 1 日の初め（今日のブロックが 0 件のとき、始業の通知をクリックしたとき、振り返りの案内から、日付の帯の「デザイン」ボタン）に右のパネルへ開くモードです。テンプレートの適用、その日のカレンダー予定、ブロックにしていない未完了タスクの一覧が並びます。タスクはチップとして並び、タイムラインへドラッグするか、選んで（強調表示になります）からタイムラインをクリックするとブロックになります。ブロックの編集などを開いて閉じると、デザインのパネルに戻ります。終わったら「完了」を押すと閉じます。

### ブロックのテンプレート（働き方のパターン）

「水曜は定例があるのでこの並び」「金曜は内省の時間を取る」といった配置を、名前を付けて保存できます。

- **保存**: 配置してから、今日のデザインのパネルの「この日の配置をテンプレートとして保存」（見ている日の配置を保存します）。設定の「テンプレート」タブでは、ブロックと時刻（HH:MM）を指定して作ったり、編集・削除したりできます（今日のデザインの「テンプレートを管理」からそのタブへ移れます）。
- **曜日の既定**: テンプレートに曜日（複数可）を割り当てておくと、その曜日の「今日のデザイン」で「水曜日のパターンを適用しますか？」と提案します。
- **適用**: テンプレートを選ぶと、作られるブロックと、既存のブロック・予定（busy）との重なりをプレビューします。重なる枠は「作らない」か「重ねて作る」かを選べます。「直前の適用を取り消す」でその適用で作ったブロックだけを消せます。
- テンプレートがまだ無いときは「よく使うパターンを保存しておくと、毎朝ワンタップで並べられます」と案内します。

## 実績

区間（自動判定でまとまった時間の単位）を一覧し、タスクの割り当てなどを確定する画面です（`log`。旧名の `review` は「要確認」の絞り込みを開きます）。

- **ツールバー**: 期間（今日・昨日・今週・先週）と、状態の絞り込み「要確認 N」「タスクなし」「すべて」。自動判定に確信が持てなかった区間が「要確認」で、既定の絞り込みです。「タスクなし」はタスクが付いていない作業・エージェントの区間です。無視した区間は「すべて」にも出しません。
- **左の一覧**: 時刻・長さ・タイトル（なければ exe 名）・種別の色の点、割り当て済みならタスク名、要確認・PC 外の印。行をクリックすると右に詳細が開きます。
- **右の詳細パネル**: 選んだ区間に次を指定して「確定」します。確定済みの区間も同じ形で付け替えられます。
  - **タスク**: 入力で絞り込んで選びます。一致するものがなければ、その場で新しいタスクを作れます。
  - **種別**: 作業・エージェント対話・会議・割り込みなど。
  - **活動**: 「コードレビュー」のような活動ラベル。
  - **この条件を常にこのタスクに**: チェックすると、その区間から帰属ルールを作り、以後は同じ条件が自動でそのタスクになります。
  - **「…」メニュー**: 「この区間を無視」「○○.exe を今後も無視」「割り込みとしてタスク化」（区間のタイトルから新しい割り込みタスクを作って割り当てます）。
- 「要確認」で確定すると、次の要確認の区間が自動で選ばれます。なくなると「確認が必要な区間はありません」と出ます。ナビの「実績」には要確認の件数が添えられます。
- 今日の画面のタイムラインの「実績」の列をクリックすると、その区間を右のパネルで開きます（同じ形で確定でき、「実績で開く」でこの画面に移れます。ドラッグは、下の「実績の補正」です）。タスクの詳細の「時間」タブの「このタスクの区間を実績で見る」からは、そのタスクの区間だけを表示します。

1 分（`review.min_sec`）未満の短い区間は、「要確認」の一覧に出さずに隠します。「短い区間 N 件を表示」のチェックで表示できます。隠した区間も削除はされず、そのまま集計に含まれます。今日の画面の「要確認」の件数は、隠している短い区間を含めず、短い区間の件数を別に添えます。なお、タスクバーやスタートメニューなどを一瞬だけ前面にした時間は、そもそも独立した区間にせず前後の作業に含めます（[設定](./configuration.md)の `collect.transient_exes`）。

確定した内容は最優先で適用され、再計算しても上書きされません。

### 無操作の時間をワンタップで仕分ける

種別が「無操作」の区間を選ぶと、詳細パネルの上に「休憩」「会議」「考えごと」「離席」のボタンが並びます。押すとその場で確定します。

| ボタン | 保存される内容 |
|---|---|
| 休憩 | 種別: 休憩 |
| 会議 | 種別: 会議 |
| 考えごと | 種別: 作業、活動: 考えごと（タスクは付けない） |
| 離席 | 種別: 休憩、活動: 離席 |

CLI では `hitoiki review idle <区間 ID>... <break|meeting|thinking|away>` です。

次の場合は、そもそも要確認の対象になりません。
- 画面ロックやスリープによる無操作が `review.auto_break_locked_min`（既定 10 分）以上続いたときは、自動で「休憩」になります（`0` で無効）。違う場合は、あとから上のボタンで付け替えられます。
- 予定（busy）と重なる無操作は、これまでどおり「会議」になります。

### 戻ってきたときの確認

予定外の無操作が `push.idle_return_min`（既定 15 分）以上続いたあと復帰すると、「さっきの N 分は、どう過ごしていましたか？」と通知します。ボタン（休憩・会議・考えごと・離席）を 1 回押すだけで、上と同じ内容で確定します。答えなくても構いません。その無操作の間に、進行中だったタスク（なければ、計画ブロックが重なっていたタスク。複数なら重なりが長いもの）があるときは、先頭に「◯◯をしていた」のボタンが付きます。読書や勉強など PC に触れない作業のときに押すと、その時間をそのタスクの「PC 外」の作業として確定します（下の[PC 外の作業](#pc-外の作業)と同じ形で、補正の一覧から取り消せます）。自動では確定しません。そのタスクの候補があるときは、長いロックで自動の「休憩」になった無操作でも尋ね、答えると自動の休憩を上書きできます（候補がなければ従来どおり尋ねません）。`push.idle_return_min = 0` か、`push.disabled_triggers` に `idle_return` を入れると出ません。

### まとめて仕分ける

区間の左のチェックで複数を選ぶと、右のパネルが「N 件を選択中（合計 ○分）」になり、同じタスク・種別・活動を一括で割り当てられます（「この条件を常にこのタスクに」も使えます。無操作の区間だけを選んだときは、ワンタップの分類も出ます）。「すべて選ぶ」で一覧全体を選べます。CLI では `hitoiki review set <区間 ID>... --task T` のように複数の ID を渡します。

### ルール化の提案

同じ exe（エージェントの区間なら作業ディレクトリ）の区間を、同じタスクにあわせて 3 回（`review.rule_suggest_min_count`）以上確定すると、一覧の上の「提案」の帯に「Orca.exe はいつもこのタスクにしますか？」と出ます（先頭の 1 件を表示し、「ほか N 件」で開きます）。「ルールにする」で帰属ルールを追加し、「今はしない」で断ります。断った組み合わせは 14 日（`review.rule_suggest_snooze_days`）出しません。ルールの追加は、すでにあるルールと同じ内容なら再利用します。CLI では `hitoiki review suggest` で一覧し、`--accept N` / `--dismiss N` で操作します。

### 無視する（ノイズのアプリ・区間）

タスクバーやスタートメニューなどのシステム系アプリ（`explorer.exe` など）は、短く前面になるだけで区間を増やします。これらは既定の「無視リスト」（`collect.ignore_exes`）に入っていて、短いものは前後の作業に含め、続いたものは「無視」の区間にします。無視の区間は集計・実績の要確認・レポート・タスクの実績・通知に数えず、今日のタイムラインには薄く表示します（今日の合計の下に「無視 N」と添えます）。記録は消えません。

- **区間を無視する**: 実績の詳細パネルの「…」メニューから「この区間を無視」、または複数選んで「N 件を無視」。今日のタイムラインでは範囲を選んで開く「実績の付け替え」で、チェックした区間を「チェックした区間を無視」できます（区間全体が対象）。同じ画面の「無視した区間」から「元に戻す」で取り消せます。CLI は `hitoiki review ignore <区間 ID>...` と `hitoiki review unignore <区間 ID>...` です。
- **このアプリを今後も無視**: 実績の詳細パネルの「…」メニューの「○○.exe を今後も無視」で無視リストに追加し、直近 7 日を再計算します。設定の「ルール」タブ（種類「無視」）や `hitoiki ignore add|remove <exe>` でも変更できます。リストから外せば元に戻ります。
- **無視の提案**: 直近 7 日の記録から、短い区間が多いアプリ（10 秒未満が 7 割以上で 20 件以上）、既知のシステム系アプリ、要確認に短い区間が何度も出ているアプリ、実績で「無視」「タスクなし」にした回数が多いアプリを、実績画面の上の「提案」の帯に「explorer.exe は短い区間が 214 件（合計 16.5分）。無視しますか？」と出します。「無視する」で追加して再計算、「今回はしない」で 30 日は出しません。ターミナル・エディタ・ブラウザ・通信・会議のアプリは提案しません。CLI は `hitoiki ignore suggest [--accept EXE] [--dismiss EXE] [--days N]` です。

### 始めたタスクを信頼する

設定 `review.trust_doing = true`（設定画面とオンボーディングにも切り替えがあります）にすると、進行中のタスクに仮で当てた時間も確認待ちにせず、そのタスクの自動判定（根拠: 進行中のタスク）として扱います。既定は従来どおり、確認待ちにします。

## 実績の補正

自動判定とあとからの仕分けでは直しにくい「この時間帯はまるごとあのタスクだった」を、範囲を選んで一度に直せます。実績の入力欄ではなく、ユーザーの確定（`segment_override`）として保存されるので、再計算しても残ります。

1. 今日の画面のタイムラインで、「実績」の列をドラッグして時間帯を選びます。ドラッグの端は、2 分（`review.snap_sec`、`0` で吸着しない）以内なら区間の境目にくっつきます。
2. 右のパネルに「実績の付け替え」が開きます。範囲に含まれる区間が一覧で出るので、チェックで対象を選び、割り当て先（タスク、「タスクなし」、「休憩」）と、任意で活動を選びます。
3. 一覧の下に「タスク X に 1時間12分を割り当て（うち PC 外 15分）。外した区間 3 件」のように、確定前の合計が出ます。「付け替える」で確定します。

最初のチェックは次のとおりです。

| 区間 | 最初のチェック | 設定 |
|---|---|---|
| 通常の作業（自動・要確認） | ON | |
| エージェント対話・見守り | ON（タスクだけ付け替え、種別は維持） | |
| ユーザーが確定済みの区間 | OFF（チェックすれば上書きできる） | `review.correct_include_confirmed` |
| 会議（カレンダー由来） | OFF | `review.correct_include_meeting` |
| 無操作・記録なし | OFF | `review.correct_include_idle` |

一覧の上の「未確定だけ」「タスクなしだけ」で絞り込め、「無操作・記録なしも含める」で無操作と記録なしをまとめて切り替えられます。範囲の境界にまたがる区間は、範囲の内側の部分だけが対象です（区間の残りは変わりません）。

### PC 外の作業

無操作や記録なし（Hitoiki が動いていなかった時間帯）を含めてチェックすると、その時間は、選んだタスクの「作業」として計上され、「PC 外」の印が付きます（タイムラインでは斜線の入った区間、一覧では「PC 外」のタグ）。会議室や紙での作業など、PC に触れていなかった時間を実績に入れるための機能です。記録なしの時間帯は、補正すると「記録なし」の斜線ではなく、その区間として表示されます。

### 取り消す

付け替えは 1 回ごとにひとまとまりで記録されます。確定の直後は「取り消す」ボタンで、あとからはタスクの詳細の「補正した時間帯」（各行の「…」メニュー）から取り消せます。取り消すと、その補正で作った確定を削除して、その時間帯を自動判定の結果に戻します（再計算するため、対象の時間帯の判定は最新のルールで作り直されます）。

CLI は `hitoiki review set --from <時刻> --to <時刻> --task <ID>`（`--dry-run` で確定せずに対象と合計だけを表示）、`hitoiki review corrections`、`hitoiki review undo-correction <ID>` です（[CLI](./cli.md)）。

## 通知

Hitoiki は、ときどき通知で「いま何してた？」などと問いかけます。ボタンを 1 回押すだけで答えられ、答えはチェックイン・ハッスル・通知の一時停止として保存されます。答えなくても構いません。

主な問いかけの場面は、始業・終業・週次の振り返り、無操作から戻ったとき、割り込みの後、会議が延びているとき、切り替えが多いとき、長時間の集中、遅い時間までの作業、そしてタスクの「緊急」「重要」のしるしに合わせた声かけです（下の「緊急・重要のタスクへの声かけ」）。1 日の上限（既定 6 件）と最小間隔（既定 60 分）があり、会議中や集中ブロックの計画中は保留されます。回数や時刻は [設定](./configuration.md#通知) で変えられ、`push.enabled = false` で止められます。

通知は Windows のトースト（ボタン付き）です。回答を求める通知は、操作する（答える、または閉じる）まで画面に残ります（設定 `push.toast_persistent`、既定 true。false だと一定時間で自動的に消えます）。更新のお知らせは残りません。出せない場合は、画面右下の小さなポップアップに切り替わります。通知本体をクリックすると、該当する画面（記録の振り返りなど）が開きます。ボタンが効かない場合は [トラブルシューティング](./troubleshooting.md#通知が出ない場合) を参照してください。

### 計画の時間になったとき

今日の計画ブロックにタスクを入れておくと、開始の時間になった（開始から 10 分以内の）とき、「今から「◯◯」の時間（10:00–11:00）です。始めますか？」と通知します。「始める」でそのタスクを進行中にし、「今回はやめる」は記録だけです。そのタスクがすでに進行中・完了・中止済み、いまの作業がそのタスクのとき、同じブロックにすでに通知したとき、無操作中には出しません。時刻に意味のある通知なので、直前に別の通知があっても出ます（「一時停止」・1 日の上限・会議中の保留は受けます。集中ブロックは、そのブロック自身の開始通知を保留しません）。止めるには `push.disabled_triggers` に `block_start` を入れます。PC に触れない作業で「始める」を押せないときは、戻ってきたときの通知の「◯◯をしていた」で、あとから入れられます。

### 緊急・重要のタスクへの声かけ

タスクに付けた「緊急」「重要」のしるしを使って、取りかかるきっかけになる通知を 2 種類出します。どちらも勤務時間内（`push.day_start_after`〜`push.day_end_at`）だけで、無操作中には出ません。

- **緊急のタスクがあります**: 緊急のしるしが付いた未完了のタスクがあり、そのどれにも取り組んでいないとき、「「◯◯」に緊急のしるしが付いています。いま取りかかりますか？」と知らせます（複数あれば「ほかに N 件」を添えます）。ボタンは「始める」（そのタスクを進行中にします）と「あとで」（何もしません）。同じ通知は `push.urgent_task_interval_min`（既定 120 分、`0` で無効）以上あけ、前回と別のタスクから順に示します。今日の計画にそのタスクの枠がこれから先にあるときや、取り組み中のときは出ません。
- **重要なタスクに少し時間を取りませんか**: 重要だが緊急ではないタスクに、`push.important_stale_days`（既定 3 日、`0` で無効）以上時間が入っていないとき、1 日 1 回まで知らせます。「ここ N 日ほど時間が入っていません」と事実を伝えるだけで、評価はしません。ボタンは「始める」、「今日の予定に入れる」（今日のデザインを開きます）、「今週は見送る」（今週はそのタスクについて出しません）。今日の計画に入っているタスクや取り組み中のタスクは対象外です。

どちらも `push.disabled_triggers` に `urgent_task` / `important_task` を入れると止められます。

- **今週、時間が入っていない KR があります**: 軸が時間・回数の KR（Objective の期間内で、スキルか紐付けたタスクがあるもの）に、今週まだ時間が入っていないとき、`push.kr_idle_weekday`（既定 3 = 水曜、`0` で無効）以降の勤務時間内に、週に 1 回まで知らせます。「◯◯に、今週はまだ時間が入っていません」と事実を伝えるだけで、評価も促しもしません。KR が複数あるときは 1 回にまとめます。ボタンは「今日の予定に入れる」（今日のデザインを開きます）と「今週は見送る」。`push.disabled_triggers` に `kr_idle` を入れると止められます。

### あとから答える（未回答の問いかけ）

通知を見逃したり、トーストが消えてしまったときは、今日画面の上の帯の「未回答の問いかけ」（「答える」）から、右のパネルで答えられます。通知と同じボタン・一言の入力欄が出ます。

- 記録（エネルギーなどのチェックイン、ハッスル）の時刻は、答えた時刻ではなく **通知が出た時刻** になります。3 時間前の通知にいま答えても、その時点の状態として記録されます。
- 無操作から戻ったときの問いかけ（「さっきの N 分は？」）には、対象の時間帯（開始〜終了）が出ます。あとから答えても、その時間帯に分類がつきます。
- 「答えない」を押すと、その通知は一覧から消えます（見送り）。見送りは「答えなかった」ものとして数えるので、答えない通知が続くと通知の間隔が自動的に長くなる仕組みはそのままです。
- 一覧に出るのは今日の分だけです。過去の分は CLI の `hitoiki push list --date D` で確認できます（[CLI](./cli.md)）。

CLI では `hitoiki push list --unanswered` と `hitoiki push answer <ID> --energy 4` / `--hassle "..."` / `--idle meeting` / `--task start` / `--dismiss` を使います。

設定画面とトレイの「通知を 1 時間止める」で一時的に止められます。通知のボタンに「今日はもういい」が出る場合は、その日の終わりまで止まります。

## タスク

タスクの作成・編集・状態変更をする画面です（`tasks`）。左にタスクの一覧、右に選んだタスクの詳細が出ます。

- **一覧（左）**: 「未完了」「完了」「すべて」で絞り込めます。各行は状態、タイトル、見積、小さな印（割り込み・緊急・重要）です。行を選ぶと右に詳細が開き、アドレスも `#/tasks/<ID>` に変わるので、ブラウザの「戻る」で前に選んでいたタスクに戻れます。「＋ タスク」を押すとタイトルの入力欄が出て、Enter で作成してそのまま選択します（Esc でやめます）。
- **詳細（右）**: 見出しにタイトルと状態があり、状態に合わせた主な操作が 1 つ出ます（未着手なら「始める」、進行中なら「完了にする」）。「…」メニューに「やめる」と「削除…」があります。KR とスキルは見出しの下にリンクのチップで出て、押すと [目標](#目標) の KR・スキルの詳細へ移ります（付け外しはこの画面の「概要」で行います）。詳細は「概要」「時間」「ルール」のタブに分かれています。「概要」は編集欄、「時間」はこれまでの時間と補正した時間帯、「ルール」は帰属ルールです。タブを切り替えても、編集中の内容は残ります。
- 状態は「未着手」「進行中」「完了」「やめた」。進行中にできるタスクは、既定では 1 つだけです（`task.single_doing`）。
- 緊急・重要のフラグ、見積もり（任意）、本文（Markdown）、スキル、KR（OKR の成果への紐付け。入力して選び、外すこともできます）、リンク（Issue など）を付けられます。スキルは入力すると既知のスキルから候補が出て（↑↓で選び、Enter か Tab かクリックで追加。外すときはチップの × か、入力欄が空のときの Backspace）、「目標」の画面にない名前は追加できません。保存ボタンは編集欄の末尾に 1 つだけで、未保存の変更があるときは画面の下に貼り付きます（Ctrl+S でも保存できます）。実績時間の入力欄はありません。実績は記録から自動で算出されます。
- 割り込みタスクは通常のタスクと区別されます。
- **保存**: 編集は「保存」ボタン（本文の下とフォームの最下部）か Ctrl+S で保存します。自動保存はしません。保存すると「保存しました」を数秒表示し、失敗したときはボタンの近くにエラーを出します。
- **未保存の確認**: 保存していない変更があると「未保存の変更があります」と表示し、保存ボタンを強調します。そのまま別のタスクを選ぶ、別の画面へ移ると、破棄してよいかを確認します（「キャンセル」で留まります）。
- **本文のプレビュー**: 本文は「編集」と「プレビュー」を切り替えられます。タスクを開いたときは、本文があればプレビュー、空なら編集です。
- **補正した時間帯**（「時間」タブ）: そのタスクへ付け替えた時間帯（[実績の補正](#実績の補正)）の一覧です。合計と PC 外の時間を確認し、「取り消す」で戻せます。
- **帰属ルール**（「ルール」タブ）: 「アプリ名」「ウインドウタイトル」「作業ディレクトリ」「リポジトリ」「URL」「ブランチ」のパターン（glob / 正規表現 / 含む）をタスクに結び付けます。条件に当たる時間は自動でそのタスクになります。各ルールは、先頭のチェックで有効/無効を切り替え（無効にしてもルールは残ります）、「編集」で対象・種類・パターン・優先度を直し、「削除」で消せます。変更すると今日の分が再計算されます（過去の日は `hitoiki rebuild` で反映します）。
- **やめると削除**: 「やめる」はタスクを「やめた」状態にして、これまでの記録（計上した時間）を残します。誤って作ったタスクは詳細の「…」メニューの「削除…」で消せます。押すと確認が出て、「計上済み 1時間20分（12 区間）と確定した割り当て 3 件が未割り当てに戻ります。帰属ルール 2 件も削除されます」のように影響を表示し、「削除する」で実行します。削除すると、そのタスクの本体・帰属ルール・スキルの紐付け・進行中の履歴・確定した割り当てと補正が消え、計上されていた時間は未割り当てに戻って実績で割り当て直す対象になります（再計算するので、直近の判定はそのときのルールで作り直されます）。計画のブロックとテンプレートの項目は消えず、タスクの指定だけが外れます（ラベルが空ならタスク名がラベルになります）。削除は元に戻せません。

### クイック入力（割り込みのとき）

割り込みなどで、考える間もなくタスクを切り替えたいときの小さな入力窓です。どの画面・どのアプリからでも、ショートカット（既定は `Ctrl+Alt+Space`。[設定](./configuration.md#クイック入力のショートカット)）かトレイの「タスクを素早く入力…」で開きます。

1. ショートカットを押すと、画面の中央上寄せに入力窓が開き、すぐ入力できます。
2. タスク名を入れると未完了のタスクが絞り込まれ、↑↓ と Enter で選ぶと、そのタスクを開始（進行中に切り替え）します。一致がなければ「新規作成: 『…』」を選んで Enter で、作成して開始します。
3. 先頭に `!` を付ける、または Tab で「割り込み: オン」にすると、新規作成するタスクを割り込み（緊急）として作ります。
4. 候補の先頭には「戻る: 〇〇」が出ます。割り込みが終わったら Enter で直前まで進行中だったタスクに戻れます（空欄のまま Enter でよい）。
5. 開始すると窓に「開始しました: 〇〇」を一瞬出して閉じます。Esc を押すか、ほかの場所をクリックして入力窓がフォーカスを失った場合も閉じます。

ショートカットは GUI アプリが動いているときだけ使えます（ヘッドレスの daemon にはありません）。他のアプリが同じ組み合わせを使っていると登録できないので、設定画面で別の組み合わせに変えてください。CLI では `hitoiki task switch` / `hitoiki task back` が同じことをします（[CLI](./cli.md)）。

## 記録

チェックイン・ハッスル・ABC の記録と、始業・終業・週次の振り返りを、1 つの時系列で見る画面です（`records`）。以前の「振り返り」の画面は、この画面に入りました（古い呼び名の `reflect` も使えます）。

- **一覧（左）**: 期間（今日・昨日・今週・先週。既定は今週）の記録を、新しいものから 1 本に並べます。1 行は、要約（チェックインは「エネルギー 4・気分 4・ストレス 2」、ハッスルは本文、ABC は A、振り返りは「終業の振り返り・回答あり」）、種類、ERG、時刻です。上の「チェックイン」「ハッスル」「ABC」「振り返り」で種類を絞れます。選んだ記録はアドレスに載り、ブラウザの「戻る」で前の選択に戻れます。
- **詳細（右）**: 行を選ぶと内容が出ます。「…」メニューに「編集」と「削除」があります（編集は詳細の中でフォームに切り替わり、記録した時刻は変わりません。削除は確認のダイアログが出ます。ハッスルを削除しても、それを元にした ABC の記録は残り、ハッスルとの紐付けだけが外れます）。ABC には、受け止め方（B）を掘り下げる問いを AI に聞くボタンがあります。
- **書く**: 右上の「＋ 記録」から種類（チェックイン・ハッスル・ABC・始業の振り返り・終業の振り返り・週次の振り返り）を選ぶと、右にその種類のフォームが出ます。保存すると、作った記録が一覧に出て選ばれます。
  - **チェックイン**: エネルギー・気分・ストレスを 1〜5 で。一言メモも書けます。
  - **ハッスル**: その日の気になったこと（デイリーハッスル）と強さ。
  - **ABC**: 出来事（A）、受け止め方（B）、感情（C）と強さ。
  - **振り返り**: 基準日（週次はその週の日）を選んで「問いを生成」を押すと、AI が問いを作り、できた振り返りが選ばれます。問いは種類ごとのフォームで答えます（`ai.structured` が有効なとき。既定では `claude` を使っている場合）。チェックインは 1〜5 のボタンとメモ（ERG は尋ねません。記録の内容から AI が判定します）、ハッスルはテキストと強さ、ABC は A（AI が記録から推測した候補で、書き換えられます）・B・C の感情と強さ・反論、自由記述は文章です。答えた問いだけが保存され、チェックイン・ハッスル・ABC は一覧にも出ます。ABC は保存後に、受け止め方を掘り下げる問いを AI に続けて聞けます。残りの問いは後から答えられます。構造化に失敗したときは、従来どおり Markdown の問いが出るので、回答を Markdown で書いて保存します。週次の振り返りの詳細には、その週の ERG の分布も出ます。
- **未回答の問いかけ**: 通知にまだ答えていないものがあると、一覧の上に「未回答の問いかけ N 件」の帯が出ます。開くと、通知と同じ選択肢でその場で答えられ、「答えない」で外せます（[通知](#通知)）。
- **ERG（存在・関係・成長）**: 記録の内容から AI が判定します（存在 = 体や生活の安心、関係 = 人とのつながり、成長 = 手応えや学び）。一覧の行と詳細に ERG が出て、AI の判定には小さく「AI」と付きます。AI が確信を持てないものは「確認待ち」と出て、詳細の提案と理由で「これでよい」（確定）か「変える」（選び直し）を選べます。上の「ERG 確認待ち N」で確認待ちだけに絞れます（確定するまで集計には入りません）。自分で付けたタグは AI で上書きされません。画面の上には期間内の件数の分布が 1 行で出るだけで、多い少ないの評価はしません。終業・週次の振り返りを作る前に未判定の記録は自動で判定され、「未判定の記録を AI で判定する」ボタンでも実行できます（記録の文章が AI に送られます。[プライバシー](./privacy.md)）。AI が未設定なら判定しません。
- 時間の使い方に良し悪しの評価はつけず、問いかけの形で寄り添います。

AI の呼び出しは、設定 `ai.command`（既定 `claude -p`）で指定したコマンドに標準入力でプロンプトを渡す方式です。Hitoiki 自身はネットワークに接続しません。コマンドが使えない環境では、[設定](./configuration.md#ai-コマンド) を見直してください。

## 目標

目標（Objective）とその成果指標（KR）、スキルを管理する画面です（`okr`）。タスクを KR やスキルに結び付けると、レポートで目標別・スキル別の時間が見られます。スキルは階層にでき、同梱のプリセットを取り込めます。複数のスキルが付いた時間は、それぞれに全時間を数えます。

左に一覧、右に選んだものの詳細が出ます。一覧は「OKR」と「スキル」の 2 つのタブで切り替えます。選んだものはアドレス（`#/okr/o/<ID>`、`#/okr/kr/<ID>`、`#/okr/skill/<ID>`）に載るので、ブラウザの「戻る」で前の選択に戻れます。

- **OKR タブ（一覧）**: Objective を見出しの行（タイトル・期間・状態）にして、その下に KR の行を並べます。KR の行には、選んだ軸の値を 1 つと、書いてある目標を並べて出します（例「19時間23分 / 目標 5 時間/週」。達成率や評価は出しません）。「＋ Objective」で追加します。Objective の行の「…」から「KR を追加」「編集」「削除…」を選べます。
- **スキルタブ（一覧）**: 親子の階層をインデントで表示します。「＋ スキル」で追加し、「プリセットを取り込む」で同梱のスキルを取り込みます。
- **詳細（右）**: Objective は編集と、配下の KR の一覧（リンク）と「＋ KR」。KR は見出しの「編集」で内容を直し、下に集計・週別の時間・スキル別・値の履歴・スキル・タスク・紐づけの提案が区画ごとに並びます。スキルは名前・親・説明の編集と、そのスキルが付いたタスク・KR の一覧（リンク）です。タスクの一覧のタイトルを押すと、[タスク](#タスク)の詳細へ移ります。
- **関係の編集は片側で**: タスクの KR・スキルは、タスクの詳細の「概要」で付け外しします（KR やスキルの側には、リンクで一覧が出ます）。KR のスキルは KR の詳細で付け外しします。KR へのタスクの紐付けは、タスクの詳細のほか、KR の詳細の「この KR のタスクを追加」「既存のタスクを紐づける」からもできます。

編集と削除は、詳細の見出しの「編集」ボタンと「…」メニューから行います。削除は確認のダイアログで影響を表示します。

- **Objective**: タイトル・説明・期間・状態（進行中／達成／やめた）を編集できます。削除すると配下の KR も消えます。KR に紐付いていたタスクは消えず、KR との紐付けだけが外れます（影響を受けるタスクの数を表示します）。
- **KR**: タイトル・目標・現在値・状態を編集でき、別の Objective へ付け替えられます。削除してもタスクは残り、紐付けだけが外れます。
  - **何を軸に見るか**: 「時間」（量が要るもの）、「回数」（「週 3 回読書」のような習慣）、「完了数」（成果物の数）から選びます（既定は時間）。回数では「取り組んだ日」とみなす 1 日の最小分数（既定 15 分）も決められます。
  - **集計**: KR の詳細に、選んだ軸の値を大きく、残りの 2 つを小さく出します。期間は Objective の期間で、無ければ直近 8 週（今日を含む週から数えます）です。時間はスキル経由と紐付けたタスク経由の作業時間の和集合（今日の合計と同じ数え方で、無操作・休憩・無視は含めません）、回数はその時間が 1 日に最小分数以上あった日の数（ローカルの日付）、完了数は「期間内に完了したタスク / 紐付いたタスクの数」（やめたタスクは数えません）です。そのほかに週ごとの時間（月曜始まりの棒）、スキル別の時間（複数のスキルが付いたタスクは各スキルに全時間を数えます）、見積の合計とそのタスクの期間内の実績を出します。目標・現在値は書いたとおりに並べるだけで、達成率の計算や評価はしません。
  - **KR のスキル（主）**: KR にスキルを付けると、そのスキル（子スキルを含む）が付いたタスク、またはスキルの活動ルールでそのスキルが付く活動にかけた時間が、その KR の時間になります。KR の詳細の「スキル」欄（タスク画面と同じ入力）と、KR を追加するときのスキル欄で付け外しします。タスクの紐付け（下記）は「このタスクも含める」補助で、スキルが付いていなくても紐付けたタスクの時間を数えます。時間と日数は、スキル経由とタスク経由を区間単位で重ならないように合算した 1 つの値で、「取り組んだ日」は合算した時間が最小分数以上の日です。内訳（スキルから / 紐付けたタスクから。両方に当てはまる区間はスキルから）は小さく添えます。完了数の軸だけは、対象を紐付けたタスクに限ります（このときカードでは紐付けが先に出ます）。事実の数値だけで、目標との比較や評価はしません。CLI は `hitoiki okr add-kr --skill` / `edit-kr --skill` / `--no-skill` です。
  - **値の履歴**: KR の詳細の「値の履歴」の区画で、現在値の変わり方と週ごとの時間を同じ週の軸で並べて見られます（棒が時間、線が各週の終わり時点の現在値。数として読める値だけを線にします）。「現在値を記録」の欄に値とメモ（任意）を入れて記録すると、現在値が更新され、履歴に残ります。KR の編集で現在値を変えたときも履歴が残ります。目標との比較や評価はしません。KR を削除すると履歴も消えます。CLI は `hitoiki okr progress` / `history` です。
  - **タスクとのつながり**: 紐付けの入口は 3 つあります。(1) タスク画面の編集で「KR」の欄に KR 名（または Objective 名）を入力して選ぶ（× で外せます）、(2) KR の詳細の「この KR のタスクを追加」にタイトルを入れて、作成と同時に紐付ける、(3) KR の詳細の「既存のタスクを紐づける」で未完了のタスクから複数選ぶ。別の KR に紐付いているタスクには「KR『…』に紐付いています。選ぶと付け替えます」と出て、付け替えになります。紐付いたタスクはカードに並び、「外す」で個別に外せます。CLI は `hitoiki okr link` / `unlink` / `show` です。
  - **紐づけの提案**: スキルも紐付けたタスクも無い KR の詳細には、名前の近いタスク・スキルが「紐づけの候補」として出ます（自動では紐付けません）。候補ごとに「付ける」（タスクは紐付け、スキルは KR のスキルに追加）か「付けない」（以後その候補は出しません）を選びます。最初は手元の名前の近さだけで探し、「AI にも聞く」を押したときだけ、AI（`ai.command` が設定されているとき）にも尋ねて合わせます。AI に送るのは KR と Objective のタイトル、タスク名、スキル名だけです。CLI は `hitoiki okr suggest <KR>`（`--no-ai` で手元だけ）/ `suggest-accept` / `suggest-reject` です。
- **スキル**: 名前・親・説明を編集できます（取り込み済みのプリセットも同じ）。削除するとタスクへの付与が外れます。子スキルがあるときは、親を付け替えて残すか、一緒に削除するかを選べます。プリセットのスキルを消しても、もう一度取り込むと戻ります。

## レポート

期間内の時間を集計する画面です（`report`）。期間（今日・昨日・今週・先週・任意の期間）と、集計の軸（タスク・活動・象限・OKR・スキル・エージェント・種別）を選びます。

画面の上には「活動量」のヒートマップがあります（GitHub の貢献グラフのような、日ごとの濃淡の表です）。週を列、曜日（月曜始まり）を行にして、今日までの直近 53 週を並べます。指標は「時間」（今日の合計と同じ数え方で、無操作・休憩・無視を含めない）、「種別」（作業・会議などの区間の種別ごとの時間）、「タスク」、「スキル」（子スキルを付けたタスクの時間も含みます）、「KR」（その KR に紐付いたタスクの時間）、「記録」（チェックイン・ハッスル・ABC・振り返りの件数。種類も選べます）です。日付はローカルのタイムゾーンで区切ります。濃さは、値のある日の分布を 4 等分した相対的な段階で、多い少ないの評価ではありません。セルにマウスを載せると日付と値が出て、クリックすると下の行にも表示します。CLI は `hitoiki heatmap` です。

## 設定

`settings` 画面は、左の項目（狭いときは上）でタブを切り替えます。選んだタブはアドレスに載ります（`#/settings/rules` など。`hitoiki ui settings` は「全般」を開きます）。数値の設定は「ラベル + 入力 + 単位」の 1 行で、説明は横の「?」で読めます。設定の内容は [設定](./configuration.md) を参照してください。

- **全般**: ログイン時の自動起動、新しいバージョンの確認（[更新の確認](./configuration.md#更新の確認)）、タイムゾーン（表示のみ）、クイック入力のショートカット、オンボーディングの再表示。
- **通知**: 問いかけの通知を受け取るか、テスト通知、1 時間止める・止めるのをやめる。戻ったときの確認の分数、緊急タスクの間隔、重要タスクの日数、時間が入っていない KR を知らせる曜日（`push.*`）。0 で無効にできる値には「0 で無効」と添えてあります。
- **判定**: 始めたタスクを信頼する、ロック・スリープで自動休憩にする分数（`review.*`）。
- **ルール**: 帰属ルール（全タスク分）、活動ルール、無視するアプリを 1 つの一覧にまとめています。上の「すべて／帰属／活動／無視」で種類を絞り、帰属はタスクでも絞れます。行には種類、パターン、行き先（タスク名・活動ラベル）、優先度が並び、無効のものには「無効」が付きます。行を選ぶと右（狭いときは下）に編集フォームが開き、行末の「…」メニューから有効/無効の切り替えと削除（無視するアプリは「外す」）ができます。「＋ ルール」で種類を選んで追加します（無視するアプリは exe 名だけ）。追加・削除すると、無視するアプリは直近 7 日を再計算します。タスク詳細の「ルール」タブとは同じルールを見ています。
- **活動ラベル**: 判定器に渡す活動の候補。追加、名前の変更（同じラベルの活動ルールも付け替わります）、外すことができます。外しても過去の時間のラベルは残ります。
- **カレンダー**: ICS ソースの追加・編集・削除。URL は秘密情報なので画面にはホスト名だけを表示します。削除するとアプリ内に取得済みの予定のコピーも消えます（カレンダー側は変わりません）。
- **テンプレート**: ブロックのテンプレートの一覧・作成・編集・削除（上の「ブロックのテンプレート（働き方のパターン）」）。
- **設定ファイル**: 設定ファイルと DB の場所、キーと値（TOML）を指定した任意の設定の書き換え、現在の設定の表示。

## トレイ

常駐中はタスクトレイにアイコンが出ます。メニューには次の項目があります。

- 現在のタスク（「いま: ...」）と今日の合計
- **タスクを切り替え**: 未完了のタスクから選んで開始
- **タスクを素早く入力…**: クイック入力の窓を開く（登録中のショートカットを併記）
- **チェックイン（エネルギー）**: 1〜5 を選ぶだけで記録
- **ハッスルを記録…**
- **新しいバージョン vX.Y.Z をダウンロード…**: 新しい版が見つかっている間だけ出る（`general.update_check` が `true` のとき）。押すとリリースページをブラウザで開く
- **UI を開く**
- **通知を 1 時間止める**（止めている間は「通知の一時停止を解除」）
- **終了**: 常駐を止める。進行中の区間は閉じて保存されます

ウインドウを閉じても常駐は続きます。ログオン時に自動で起動したい場合は `general.autostart` を有効にします（既定で有効）。
