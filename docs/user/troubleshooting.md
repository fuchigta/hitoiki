# トラブルシューティング

うまく動かないときは、まず `hitoiki doctor` を実行してください。

## hitoiki doctor

収集・DB・設定・エージェントログ・カレンダー・通知・判定器・AI コマンドの状態を、`OK` / `WARN` / `ERROR` で表示します。

```
状態  項目      内容
OK    config    設定ファイルはありません（既定値を使用）: ...
OK    db        ...
OK    collect   ...
OK    agent     ...
OK    calendar  カレンダーは未設定です
OK    notify    ...
OK    judge     判定器は無効です
OK    ai        claude が見つかりました
```

| 項目 | 見ているもの |
|---|---|
| `config` | 設定ファイルを読めるか（書式の誤りはここに出ます） |
| `db` | DB があり、開けるか |
| `collect` | 収集データがあるか、常駐プロセスが起動しているか |
| `agent` | Claude Code / Codex のログが見つかるか、最後に取り込んだ時刻 |
| `calendar` | カレンダーの設定 |
| `notify` | 通知（常駐アプリ側で確認する項目です。ヘッドレスでは通知を出しません） |
| `judge` | 判定器の設定 |
| `ai` | `ai.command` の実行ファイルが見つかるか |

`--network` を付けると、カレンダーの取得と判定器への疎通も実際に試します（このときだけネットワークを使います）。`--json` で機械可読な出力にもできます。

初めて起動する前は、DB や収集データが無いため `WARN` が出ます。常駐アプリを起動して少し使えば解消します。

## 通知が出ない場合

- 設定画面の「テスト通知を出す」（またはオンボーディングの同名のボタン）で確認します。
- 出ないときは、Windows の通知設定（アプリごとの通知、集中モード／サイレントモード）を確認してください。`push.enabled = false`、通知の一時停止（トレイの「通知の一時停止を解除」）も確認します。
- 通知は 1 日の上限（`push.daily_limit`）や最小間隔、会議中・集中ブロック中の保留で、意図して出ないことがあります（[日々の使い方](./daily-use.md#通知)）。
- トーストを出せない環境では、画面右下の小さなポップアップに切り替わります。
- **トーストのボタンや入力欄の応答は、環境（Windows のバージョン、集中モード、通知設定）によって動作を十分には確認できていません。** ボタンが効かないときは、通知本体をクリックして画面を開き、そこから答えてください。
- `hitoiki daemon`（ヘッドレス）で動かしているときは、トースト通知を出しません（ログのみ）。

## 記録が抜ける

- 常駐していなければ記録されません。トレイにアイコンがあるか、`hitoiki doctor` の `collect` が常駐プロセスを認識しているかを確認してください。ログオン時に自動で起動するには `general.autostart` を有効にします。
- **Hitoiki 自身のウインドウを操作している時間は、既定で記録しません**（`collect.record_self`）。
- 除外ルール（`collect.exclude`）に一致したウインドウ（パスワードマネージャ、プライベートブラウズなど）は、内容を保存しません。
- PC がロックまたはスリープしている間と、無操作の時間（`collect.idle_threshold_sec`、既定 120 秒）は、作業としては数えません。
- Claude Code / Codex との対話時間が出ないときは、`hitoiki doctor` の `agent` を確認し、`hitoiki agent import` で手動取り込みを試します。対話時間として数えるのは、そのセッションのウインドウ（`collect.terminal_exes` に含まれるアプリ）が前面にいた時間だけです。VS Code や別のターミナルアプリを使う場合は、そのアプリの exe 名を `collect.terminal_exes` に追加してください。
- 収集器やログ監視の設定を変えたときは、常駐アプリの再起動が必要です。
- 帰属が期待どおりでないときは、`hitoiki rebuild` で再計算できます。

## SmartScreen の警告が出る

コード署名が無いため、初回の実行時に表示されることがあります。「詳細情報」→「実行」を選びます。zip の場合は、展開前に zip のプロパティで「ブロックの解除」にチェックを入れても回避できます。手順は [インストール](./install.md#smartscreen-の警告が出る場合) を参照してください。

## daemon と app の関係

常駐処理は同時に 1 つだけです（名前付きパイプが使用中かで判定します）。

- `hitoiki-app.exe` は、起動するとトレイに常駐し、収集・取り込み・再計算・カレンダー同期・通知をまとめて行います。
- `hitoiki daemon` は、同じ常駐処理を画面なしで動かします。トースト通知は出ません。
- `hitoiki daemon` が動いている間に `hitoiki-app.exe` を起動すると、アプリは画面とトレイだけで動き、収集は daemon が行います（画面とトレイにその旨が表示されます）。アプリを常駐の主体にしたいときは、先に `hitoiki daemon` を止めてください（Ctrl+C）。
- 二重に起動しようとしても、2 つ目は起動しません。
- CLI（`hitoiki ...`）は常駐していなくても動きます。常駐処理に変更を伝えられなくても、CLI の操作は失敗しません。

## それでも直らないとき

- ログは `%LOCALAPPDATA%\hitoiki\logs\` にあります（日次ローテーション）。ウインドウタイトルやプロンプトの内容は出力しない作りです。
- `hitoiki config path` で設定ファイルの場所を確認できます。設定の書式が壊れている場合、`hitoiki doctor` の `config` に出ます。
- 不具合は [Issues](https://github.com/fuchigta/hitoiki/issues) に報告してください。
