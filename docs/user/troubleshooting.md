# トラブルシューティング

うまく動かないときは、まず `hitoiki doctor` を実行してください。

## hitoiki doctor

収集・DB・設定・エージェントログ・カレンダー・通知・判定器・AI コマンドの状態を、`OK` / `WARN` / `ERROR` で表示します。

```
状態  項目      内容
OK    config    設定ファイルはありません（既定値を使用）: ...
OK    db        ...
OK    collect   ...
OK    agent     ...
OK    calendar  カレンダーは未設定です
OK    notify    ...
OK    judge     判定器は無効です
OK    ai        claude が見つかりました
```

| 項目 | 見ているもの |
|---|---|
| `config` | 設定ファイルを読めるか（書式の誤りはここに出ます） |
| `db` | DB があり、開けるか |
| `collect` | 収集データがあるか、常駐プロセスが起動しているか、直近 24 時間に記録が止まっていた時間（10 分以上で `WARN`。PC を終了していた時間も含みます） |
| `agent` | Claude Code / Codex のログが見つかるか、最後に取り込んだ時刻、直近 24 時間のプロンプトのうちウインドウに対応付けできなかった件数と、そのときの前面アプリの exe 名（ウインドウタイトルは出しません） |
| `calendar` | カレンダーの設定 |
| `notify` | 通知（常駐アプリ側で確認する項目です。ヘッドレスでは通知を出しません） |
| `judge` | 判定器の設定 |
| `ai` | `ai.command` の実行ファイルが見つかるか |

`--network` を付けると、カレンダーの取得と判定器への疎通も実際に試します（このときだけネットワークを使います）。`--json` で機械可読な出力にもできます。

初めて起動する前は、DB や収集データが無いため `WARN` が出ます。常駐アプリを起動して少し使えば解消します。

## 通知が出ない場合

- 設定画面の「テスト通知を出す」（または「はじめに」画面の同名のボタン）で確認します。
- 出ないときは、Windows の通知設定（アプリごとの通知、集中モード／サイレントモード）を確認してください。`push.enabled = false`、通知の一時停止（トレイの「通知の一時停止を解除」）も確認します。
- 通知は 1 日の上限（`push.daily_limit`）や最小間隔、会議中・集中ブロック中の保留で、意図して出ないことがあります（[日々の使い方](./daily-use.md#通知)）。
- トーストを出せない環境では、画面右下の小さなポップアップに切り替わります。
- **トーストのボタンや入力欄の応答は、環境（Windows のバージョン、集中モード、通知設定）によって動作を十分には確認できていません。** ボタンが効かないときは、通知本体をクリックして画面を開き、そこから答えてください。
- 回答を求める通知は、操作するまで画面に残ります（`push.toast_persistent`、既定 true）。自動で消えてほしいときは `false` にします。
- **見逃した通知・消えた通知・アクションセンターに入った通知のボタンは、常駐アプリに届かないことがあります**（未署名・非パッケージのアプリでは、トーストが画面から外れたあとの操作を確実に受け取れる保証がありません。集中モードのときは最初からアクションセンターに入ります）。その場合は、今日画面の「未回答の問いかけ」から答えてください。通知と同じ選択肢で答えられ、記録の時刻は通知の時刻になります。CLI なら `hitoiki push list --unanswered` と `hitoiki push answer` です。
- `hitoiki daemon`（ヘッドレス）で動かしているときは、トースト通知を出しません（ログのみ）。

## 記録が抜ける

- トレイのメニューの先頭（アイコンにカーソルを乗せたときの表示も同じ）に「記録中」か「記録停止中」が出ます。記録が止まっていた時間帯は、今日画面のタイムラインに斜線の「記録なし」で、`hitoiki log` に「記録なし」の行で表示されます。無操作・ロック・スリープ、Hitoiki 自身のウインドウ、除外したウインドウの時間は、収集が動いたうえでの空白なので「記録なし」とは別です。
- 「記録なし」の原因は、PC の電源が切れていた、常駐アプリが終了していた（クラッシュを含む）、収集スレッドが止まった、のいずれかです。ログ（下記）の `収集を開始しました` / `収集を停止しました` / `収集スレッドが停止要求なしに終了しました` の行で見分けられます。ログの時刻と「記録なし」の時間帯を突き合わせてください。
- 常駐していなければ記録されません。トレイにアイコンがあるか、`hitoiki doctor` の `collect` が常駐プロセスを認識しているかを確認してください。ログオン時に自動で起動するには `general.autostart` を有効にします。
- **Hitoiki 自身のウインドウを操作している時間は、既定で記録しません**（`collect.record_self`）。
- 除外ルール（`collect.exclude`）に一致したウインドウ（パスワードマネージャ、プライベートブラウズなど）は、内容を保存しません。
- PC がロックまたはスリープしている間と、無操作の時間（`collect.idle_threshold_sec`、既定 120 秒）は、作業としては数えません。
- Claude Code / Codex との対話時間が出ないときは、`hitoiki doctor` の `agent` を確認し、`hitoiki agent import` で手動取り込みを試します。対話時間として数えるのは、そのセッションのウインドウが前面にいた時間だけです。ウインドウは、プロンプトを送った時に前面だったアプリ（`collect.terminal_exes` / `collect.agent_host_exes` に含まれるアプリ。Orca、Cursor、Windsurf などは既定で入っています）から決めます。一覧に無いアプリでも、ブラウザ・通過系・コミュニケーション系・Hitoiki 自身でなければ、既定（`agent.bind_unlisted`）でそのウインドウを使います。それでも対応付けできなかったプロンプトは `hitoiki doctor` の `agent` に件数と前面アプリの exe 名が出るので、そのアプリを `collect.agent_host_exes` に追加してください。
- 収集器やログ監視の設定を変えたときは、常駐アプリの再起動が必要です。
- 帰属が期待どおりでないときは、`hitoiki rebuild` で再計算できます。

## SmartScreen の警告が出る

コード署名が無いため、初回の実行時に表示されることがあります。「詳細情報」→「実行」を選びます。zip の場合は、展開前に zip のプロパティで「ブロックの解除」にチェックを入れても回避できます。手順は [インストール](./install.md#smartscreen-の警告が出る場合) を参照してください。

## daemon と app の関係

常駐処理は同時に 1 つだけです（名前付きパイプが使用中かで判定します）。

- `hitoiki-app.exe` は、起動するとトレイに常駐し、収集・取り込み・再計算・カレンダー同期・通知をまとめて行います。
- `hitoiki daemon` は、同じ常駐処理を画面なしで動かします。トースト通知は出ません。
- `hitoiki daemon` が動いている間に `hitoiki-app.exe` を起動すると、アプリは画面とトレイだけで動き、収集は daemon が行います（画面とトレイにその旨が表示されます）。アプリを常駐の主体にしたいときは、先に `hitoiki daemon` を止めてください（Ctrl+C）。
- 二重に起動しようとしても、2 つ目は起動しません。
- CLI（`hitoiki ...`）は常駐していなくても動きます。常駐処理に変更を伝えられなくても、CLI の操作は失敗しません。

## それでも直らないとき

- 記録（調子・気になったこと・捉え直し）が消えたように見えるときは、ログの `記録を削除しました` の行（種類 `entity`・`id`・呼び出し元 `caller` が `cli` か `app`）で、削除の操作があったかを確認できます（本文・メモは出しません）。AI 振り返りの回答が作った記録を消すと、削除の確認に「振り返り（日付・種類）の回答から参照されています」と出て、振り返りの画面と `hitoiki reflect show` には「この回答の記録は削除されています」と表示されます。
- ログは `%LOCALAPPDATA%\hitoiki\logs\hitoiki.log.<日付>` にあります（日次ローテーションで 14 日分。常駐アプリ `hitoiki-app.exe` も `hitoiki daemon` も同じ場所に書きます）。起動・終了・収集の開始と停止・収集スレッドの異常終了を記録します。ウインドウタイトルやプロンプトの内容は出力しない作りです。
- `hitoiki config path` で設定ファイルの場所を確認できます。設定の書式が壊れている場合、`hitoiki doctor` の `config` に出ます。
- 不具合は [Issues](https://github.com/fuchigta/hitoiki/issues) に報告してください。
